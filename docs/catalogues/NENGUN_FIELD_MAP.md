## Callout vs. OEM number

Modeled as two entirely separate fields from end to end, per the integration request's explicit requirement:

```
CatalogueDiagram → DiagramCallout.display/.normalized (e.g. "74004")
                          ↓ partIds
                     CataloguePart
                          ↓ partId
                     ReferenceNumber.original/.normalized, type OEM_OE (may be absent)
```

`src/integrations/catalogues/nengun/mapper.ts` enforces this: a `NengunPartRow.calloutNumber` never becomes a `ReferenceNumber`, and a row with no `oemPartNumber` produces a `DiagramCallout` with zero associated `ReferenceNumber` rows rather than reusing the callout value as a stand-in OEM number. Covered by `tests/nengun-provider.test.ts`.

## Image handling

Per the integration request's explicit instruction not to auto-copy Nengun artwork: `mapNengunDiagramPage` sets `CatalogueImage.rights = "EXTERNAL_REFERENCE"` and `CatalogueImage.url = ""` unconditionally — the source image URL is recorded only in `attribution` text and `Provenance.sourceUrl`, never in the field a `<img src>` would read. `canDisplayImage()` already excludes `EXTERNAL_REFERENCE` from rendering; withholding the URL at creation time means no caller can bypass that gate even if it forgets to check it. The application's own original SVG diagram (`public/diagrams/demo-headlamp.svg`) is used for all development/demo purposes.

## Source vs. company data

The mapper produces only `CataloguePart` (reference) records — never a `Part` (company product). No cost, price, SKU, warehouse, or stock field exists anywhere in the mapper's output (tested). "Add to My Products" remains the only path from a mapped Nengun reference record to a commercial product, exactly as for every other catalogue source.

## Search

Callout numbers (`DiagramCallout.normalized`) are deliberately **not** added to the repository's global cross-vehicle number index (`ReferenceRepository`'s `numberIndex`, built only from `ReferenceNumber` entries). Per this integration's explicit requirement, callout numbers are not globally unique OEM identifiers, so a global exact-match search treating them as such would produce false-positive cross-vehicle matches. Callout lookup instead stays vehicle/diagram-aware by construction: reaching a callout requires first navigating make → model → variant → category → diagram, which scopes it correctly. OEM numbers, by contrast, are fully searchable globally as before.

## Known limitations

- "Diagram group" and "Color" have no observed example from any of the three sources listed at the top of this document, so no field was added for them — adding one now would mean inventing structure the source has not been confirmed to expose, which the integration request explicitly disallows.
- Price/quote/status text is recorded in the historical fixture only (`src/data/nengun-headlamp.ts`) and is not produced by the new mapper at all; if a licensed feed later supplies structured pricing, it should inform a supplier cost record, not a company selling price, and that mapping is not yet designed.
